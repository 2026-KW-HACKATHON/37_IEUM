# 이음 (IEUM)

> **어르신의 일상 속 도움과 대학생의 비대면 봉사활동을 연결하는 웹 플랫폼**

이음은 어르신과 가족이 생활 속에서 필요한 도움을 요청하면, 운영자가 이를 검토하여 대학생이 수행할 수 있는 비대면 봉사활동으로 구체화하고 연결하는 서비스입니다.

---

## 1. 서비스 한눈에 보기

| 대상 | 필요한 것 | 이음이 제공하는 것 |
| --- | --- | --- |
| 어르신 | 생활 속 작은 도움, 디지털 안내, 대화·기록 등 | 도움 요청 및 활동 결과 확인 |
| 가족 | 어르신을 대신한 도움 요청 | 대리 의뢰 및 진행 상황 확인 |
| 대학생 | 참여하기 쉬운 봉사활동 | 비대면 활동 탐색·신청·수행 |
| 운영자 | 의뢰와 봉사활동의 체계적인 관리 | 검토·모집·배정·결과 인증 |

> 도움이 필요한 사람의 일상과, 도움을 주고 싶은 대학생의 시간을 잇습니다.

---

## 2. 문제 정의

| 대상 | 문제 상황 | 서비스에서의 접근 |
| --- | --- | --- |
| 어르신 | 디지털 기기, 생활 정보, 취미, 대화 등 일상적인 도움이 필요할 수 있음 | 작은 생활 요구를 구체적인 활동으로 연결 |
| 어르신 | 온라인 서비스 이용 자체가 어려울 수 있음 | 가족이 대신 의뢰할 수 있도록 구성 |
| 가족 | 부모님의 도움 필요를 대신 해결하고 싶어도 적절한 방법을 찾기 어려움 | 가족 대리 의뢰 및 결과 확인 제공 |
| 대학생 | 봉사활동을 찾기 어렵고 시간·장소 제약이 존재 | 비대면 중심의 봉사활동 제공 |

---

## 3. 서비스 목표

어르신의 요청을 운영자가 확인하고 봉사활동으로 수행할 수 있는 형태로 재구성한 뒤, 대학생이 참여하고 그 결과를 확인할 수 있는 구조를 만드는 것을 목표로 합니다.

| 목표 | 내용 |
| --- | --- |
| 도움의 연결 | 어르신의 생활 속 필요한 도움을 대학생과 연결 |
| 봉사활동 접근성 향상 | 시간과 장소의 제약을 줄인 비대면 활동 제공 |
| 가족의 참여 지원 | 어르신이 직접 이용하기 어려운 경우 가족이 대신 의뢰 |
| 활동의 구체화 | 단순한 요청을 수행 가능한 봉사활동 단위로 전환 |
| 과정 관리 | 모집부터 배정, 활동, 결과 제출까지 관리 |
| 결과 확인 | 결과물과 활동일지를 통해 활동 수행 여부 확인 |

## 4. 이음의 핵심 차별점

### 4-1. 단순 심부름이 아닌 인증 가능한 봉사활동으로 재구성

운영자가 요청 내용을 확인하고, 대학생이 실제로 수행할 수 있는 봉사활동 단위로 구체화합니다.

예를 들어 단순한 스마트폰 사용 도움 요청을 받았을 때도, 요청을 그대로 전달하는 대신 생활에 필요한 기능을 정리하고 안내하는 활동으로 구성할 수 있습니다.

이를 통해 '도움을 부탁하는 서비스'와 '봉사활동에 참여하는 서비스' 사이의 연결 과정을 만들었습니다.

### 4-2. 어르신 본인과 가족을 함께 고려

디지털에 익숙하지 않은 어르신을 대신하여 가족들이 어르신을 위한 서비스를 요청할 수 있도록 합니다.

따라서 이음은 어르신 본인뿐 아니라 가족이 어르신을 대신하여 의뢰하는 경우를 주요 사용자 흐름에 포함했습니다.

| 의뢰 유형 | 이용 방식 |
| --- | --- |
| 어르신 본인 | 직접 필요한 도움을 등록 |
| 가족 | 어르신을 대신하여 도움 요청 |
| 활동 이후 | 진행 상황 및 결과 확인 |

이를 통해 어르신의 디지털 접근성 문제를 보완하면서 가족도 서비스 과정에 참여할 수 있도록 했습니다.

### 4-3. 비대면 봉사활동 중심

대학생의 참여 장벽을 낮추기 위해 직접 방문이 필요한 활동보다 온라인 환경에서 수행할 수 있는 활동을 우선적으로 구성했습니다.

| 활동 유형 | 활동 예시 |
| --- | --- |
| 생활·디지털 안내 | 스마트폰 기능 안내, 디지털 서비스 이용 방법, 생활 정보 탐색 |
| 생활·취미 키트 | 맞춤형 활동지 제작, 취미·생활 관련 자료 및 키트 구성 |
| 말벗·기록 | 비대면 대화, 인터뷰, 어르신의 이야기와 일상 기록 |

활동 자체뿐 아니라 결과물을 남길 수 있도록 구성합니다.

## 5. 전체 사용자 흐름

```text
[어르신 / 가족]
      │
      ▼
  도움 요청 등록
      │
      ▼
[운영자]
  요청 내용 검토
      │
      ▼
 봉사활동 등록
      │
      ▼
 모집 시작
      │
      ▼
[대학생]
  활동 탐색·신청
      │
      ▼
[운영자]
  대학생 배정
      │
      ▼
[대학생]
  활동 수행
      │
      ▼
 결과물·활동일지 제출
      │
      ▼
[운영자]
  제출물 검토
      │
      ▼
  내부 인증
      │
      ▼
[의뢰자]
  결과 확인
```

### 단계별 역할

| 단계 | 사용자 | 주요 내용 |
| --- | --- | --- |
| 1 | 어르신·가족 | 생활 속 도움 요청 |
| 2 | 운영자 | 요청 내용 검토 및 승인 |
| 3 | 운영자 | 봉사활동 형태로 구체화 및 등록 |
| 4 | 운영자 | 활동 모집 시작 |
| 5 | 대학생 | 활동 확인 및 신청 |
| 6 | 운영자 | 참여 대학생 배정 |
| 7 | 대학생 | 배정된 활동 수행 |
| 8 | 대학생 | 결과물·활동일지·증빙 제출 |
| 9 | 운영자 | 제출물 검토 및 내부 인증 |
| 10 | 의뢰자 | 완료된 활동 및 결과 확인 |

> **참고:** 의뢰 승인과 모집 시작은 별도의 단계입니다. 의뢰가 승인되었다고 자동으로 대학생 모집이 시작되지 않으며, 운영자가 활동 내용을 등록하고 모집을 시작한 이후 대학생이 신청할 수 있습니다.

## 7. 봉사활동 구성

현재 이음에서는 비대면으로 수행하기 적합하고, 활동 결과를 확인할 수 있는 세 가지 유형을 중심으로 구성했습니다.

| 유형 | 목적 | 예시 |
| --- | --- | --- |
| 생활·디지털 안내 | 일상적인 디지털 활용 지원 | 스마트폰 사용법, 디지털 서비스 안내 |
| 생활·취미 키트 | 취미·생활 활동을 위한 자료 제공 | 맞춤형 활동지, 취미 키트 제작 |
| 말벗·기록 | 대화와 기록을 통한 교류 | 비대면 말벗, 인터뷰, 이야기 기록 |

향후에는 실제 지역사회 수요와 기관 협력 여부에 따라 활동 유형을 추가할 수 있도록 확장성을 고려했습니다.

## 8. 운영자 중심의 서비스 구조

이음에서 운영자는 단순한 관리자 역할이 아니라 의뢰와 봉사활동 사이를 연결하는 핵심 역할을 담당합니다.

| 운영 단계 | 운영자 역할 |
| --- | --- |
| 의뢰 접수 | 요청 내용과 활동 가능 여부 확인 |
| 의뢰 검토 | 부적절하거나 수행하기 어려운 요청 검토 |
| 활동 구성 | 요청을 대학생이 수행 가능한 활동으로 구체화 |
| 모집 | 활동 내용과 정원을 설정하고 모집 시작 |
| 배정 | 신청자를 확인하고 활동에 배정 |
| 활동 관리 | 활동 상태 및 진행 상황 확인 |
| 결과 검토 | 결과물·활동일지·증빙 확인 |
| 내부 인증 | 활동 결과를 검토하고 서비스 내 인증 처리 |

이러한 구조를 통해 **'어떤 활동으로 연결하고 실제로 완료되었는가'**까지 관리합니다.

---

## 9. 봉사활동 인증

노원구 자원봉사센터에 자문하여 실제 운영 중인 비대면 봉사 방식을 안내받았습니다. 이를 통해해 봉사 방식에 대해 안내받고, 구체적으로 조사했습니다.

---

## 10. 지역사회와의 연결

지역 내 어르신에게 필요한 생활 속 도움을 발견하고, 대학생의 시간과 역량을 봉사활동으로 연결하는 것을 목표로 합니다.

| 지역 문제 | 이음의 연결 |
| --- | --- |
| 생활 속 작은 도움의 공백 | 도움 요청으로 접수 |
| 어르신의 디지털 접근성 문제 | 가족 대리 의뢰 |
| 대학생의 봉사활동 참여 기회 부족 | 비대면 봉사활동 모집 |
| 활동 결과 확인의 어려움 | 결과물·활동일지 제출 및 검토 |

향후 지역 복지기관, 자원봉사기관 등과의 협력이 이루어진다면 지역 단위의 봉사활동 플랫폼으로 확장할 수 있습니다.

## 13. 데이터 및 파일 관리

서비스 운영에 필요한 의뢰, 활동, 신청, 배정 등의 데이터는 Supabase를 기반으로 관리합니다.

활동 과정에서 제출되는 결과물과 증빙 파일은 비공개 저장소를 사용하며, 사용자 역할과 데이터 소유 관계를 고려하여 접근하도록 구성했습니다.

| 데이터 | 관리 방식 |
| --- | --- |
| 사용자 계정 | Supabase Auth |
| 사용자 정보 | PostgreSQL |
| 도움 요청 | PostgreSQL |
| 봉사활동 | PostgreSQL |
| 신청·배정 | PostgreSQL |
| 결과물·증빙 | 비공개 Supabase Storage |

## 14. 현재 구현된 사용자 경험

의뢰자, 대학생, 운영자의 역할을 분리하여 각 사용자에게 필요한 화면을 제공합니다.

- 의뢰자는 도움 요청 이후 활동 진행 상태와 결과를 확인할 수 있습니다.
- 대학생은 모집 중인 활동을 확인하고 신청한 뒤 배정된 활동을 수행할 수 있습니다.
- 운영자는 의뢰 승인과 봉사활동 등록, 모집, 배정, 결과 검토를 순차적으로 처리할 수 있습니다.
- Supabase 환경에서는 주요 데이터 변경이 사용자 화면에 실시간으로 반영되도록 구성했습니다.
- 로컬 환경에서는 별도의 Supabase 연결 없이 시연할 수 있는 저장소 모드를 제공합니다.

## 16. 기대 효과

### 어르신·가족

- 일상에서 필요한 도움을 보다 쉽게 요청할 수 있습니다.
- 어르신이 직접 서비스를 이용하기 어려운 경우 가족이 대신 요청할 수 있습니다.
- 진행 중인 활동과 완료된 결과를 확인할 수 있습니다.

### 대학생

- 시간과 장소의 제약이 적은 봉사활동에 참여할 수 있습니다.
- 모집된 활동 중 자신의 관심과 상황에 맞는 활동을 선택할 수 있습니다.
- 결과물과 활동일지를 통해 봉사활동의 과정을 기록할 수 있습니다.

### 지역사회

- 기존 봉사활동으로 연결되기 어려웠던 작은 생활 속 도움을 활동 단위로 구체화할 수 있습니다.
- 지역 내 도움을 필요로 하는 사람과 봉사 참여자를 연결하는 기반을 마련할 수 있습니다.
- 향후 지역 기관과의 협력을 통해 활동 범위를 확장할 수 있습니다.

npm install
