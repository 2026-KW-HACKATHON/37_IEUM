# 이음 (IEUM)

> **어르신의 일상 속 도움을 대학생의 비대면 봉사활동으로 연결하는 웹 플랫폼**

어르신과 가족이 생활 속 도움이 필요한 영역을 의뢰하면, 운영자가 이를 비대면 봉사활동 단위로 재구성하여 대학생과 매칭합니다. 단순 매칭에 그치지 않고 **의뢰 접수부터 활동 검토, 결과물 제출 및 내부 인증까지의 전 과정을 단일 흐름으로 제공**합니다.

---

## 1. 기획 배경 및 문제 정의

| 대상 | 현황 및 문제점 | 이음의 해결 방식 |
| :--- | :--- | :--- |
| **어르신 & 가족** | 디지털 기기 사용, 생활 정보 탐색, 대화 등 일상 속 소규모 도움 필요. 직접 요청 시 디지털 접근성 장벽 존재. | 가족 대리 의뢰 창구 지원. 일상 요구를 체계적인 활동 과제로 구체화. |
| **대학생** | 봉사 참여 의지는 높으나, 유의미한 활동처 발굴 및 시공간적 일정 조율에 어려움. | 비대면 기반 활동 제공으로 참여 장벽 완화, 결과물·활동일지 기반의 체계적 기록 관리. |

---

## 2. 서비스 핵심 차별점

* **심부름이 아닌 ‘봉사활동’으로의 재구성**  
  어르신의 단순 요구를 그대로 전달하지 않고, 운영자가 검토하여 실제 봉사활동으로 수행 가능한 형태로 가공합니다.
* **어르신 본인 + 가족을 함께 의뢰자로**  
  디지털 서비스 이용이 어려운 어르신을 위해 가족이 대신 의뢰하는 구조를 제공합니다.
* **비대면 중심의 봉사활동 설계**  
  직접 방문하지 않아도 가능한 활동부터 시작하여 대학생의 시공간 제약을 낮췄습니다.  
  * **생활·디지털 안내:** 스마트폰 사용법, 생활 정보 안내 등  
  * **생활·취미 키트:** 맞춤형 활동지 및 키트 제작  
  * **말벗·기록:** 비대면 인터뷰 및 대화 기록, 일상 정리  
* **‘도움 요청’에서 끝나지 않는 운영 구조**  
  도움 요청에서 끝나는 것이 아니라, 제출물 검수와 서비스 내부 인증 절차를 거쳐 실제 활동이 완료되었는지 확인합니다.

---

## 3. 핵심 사용자 흐름

1. **[어르신 / 가족]** 도움 요청
2. **[운영자]** 요청 검토 및 승인
3. **[운영자]** 봉사활동 등록 및 모집 시작
4. **[대학생]** 활동 신청
5. **[운영자]** 봉사자 배정
6. **[대학생]** 활동 수행 및 결과물·활동일지 제출
7. **[운영자]** 검토 및 내부 인증 완료
8. **[의뢰자]** 최종 결과 확인

> 💡 **안내사항**  
> 현재 인증 완료는 **이음 서비스 내부의 결과 검토**를 의미하며, 1365 공식 봉사시간 등록을 의미하지 않습니다. 향후 관련 기관과의 협력 및 절차가 마련될 경우 공식 봉사활동 연계를 확장할 수 있도록 구조를 설계했습니다.

| 역할 | 주요 기능 |
| :--- | :--- |

| **운영자**<br>(`/admin`) | • 의뢰 검토, 승인 및 봉사활동 등록<br>• 대학생 모집 및 배정 관리<br>• 결과물·활동일지 검토 및 내부 인증 |

## 5. 기술 구성 및 구조

### Tech Stack

* **Frontend:** React 19, Vite 8, JavaScript
* **Backend & DB:** Supabase (Auth, PostgreSQL, Storage, Edge Functions)
* **External APIs:** Kakao 우편번호 서비스, Naver Cloud SENS (선택 연동)
* **UI/UX:** 반응형 웹 UI 지원, 사용자 화면과 `/admin` 운영자 화면 분리
